# Template: PM Case Library

Output format — Google Doc, one single living document at
`40_PM_Case_Library\pm_case_library`. Personal reference only (not shared)
— cross-project, real project/client names and real situations are fine
here, same as any other Drive-internal M2 document. Organized by
**theme/pattern**, not by project — the whole point is comparing how the
same kind of situation played out across different projects/clients, so a
reader should be able to find "cases like this one" without already
knowing which project it came from.

One case = one situation + what we did + what happened + the takeaway.
File it under the theme it best matches; add a new H3 theme only once 3+
cases would actually cluster under it — until then, new cases go under
"Recent / Unsorted Cases". Insert a new case at the **end** of its theme
section (or the Unsorted section), never at a heading's own start index —
see `project-knowledge-roles/SKILL.md`, "Structural Format" for why (the
Docs API heading-inheritance bug this avoids). Once a theme section passes
roughly 800 words or accumulates enough sub-clusters of its own, split it
further with its own sub-headings — same threshold as the Project
Knowledge lane's knowledge bases.

Each case entry, one paragraph:

> **[Project, YYYY-MM-DD]** Situation — what happened, in context. Approach
> — what we (or the PM/client side) actually did. Outcome — what resulted,
> including if it didn't work. Takeaway — the reusable lesson, phrased so
> it's useful without the specific project's context.

### <Theme, added once it earns one>

Example candidate themes, none pre-created — name them from what actually
shows up, don't force cases into a theme that doesn't fit: client scope

speed, team capacity vs. delivery pressure, handling an underperforming
or disengaged team member on a client-facing project, vendor/subcontractor

communication with the client, onboarding a new team onto an unfamiliar
