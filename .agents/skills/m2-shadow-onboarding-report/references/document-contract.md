# Document Contract

Primary output is chat-ready text — the weekly block embedded in the
project's regular status, and short milestone one-liners — same
convention as `m2-project-status-report`.

## Purpose

Use this reference for the Shadow Onboarding weekly block and milestone
notifications.

## Expected Output

Short chat-ready text, Markdown/plain text. Do not use CSV.

## Target Folder

If a copy is saved:

`G:\My Drive\QA_Management\20_M2_Project_Management\<Project>\private\status_reports`

Suggested naming: `shadow_onboarding_<Project>_<Shadow>_YYYY-MM-DD.md`

## Versioning

Weekly blocks are event artifacts for that week — do not overwrite a
prior week's saved copy. Milestone notifications aren't saved separately
unless the user asks.

## Source Rules

- Prior weeks' blocks for the same face-shadow pair establish the trend
  — read them before drafting the next one.
- The handoff-quality field needs a real signal (daily context transfer
  observed, or not) — don't infer it from task completion alone.

## Missing Evidence

If the week's task/blocker/handoff evidence is thin, write the block
anyway with an explicit gap note rather than skipping the week or
inventing content — same fallback convention as
`m2-project-status-report`.

## Language

Russian by default. Preserve standard English terms as-is.
